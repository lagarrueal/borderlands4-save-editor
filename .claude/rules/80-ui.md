UI Rules

The UI should expose game concepts rather than implementation details.

Primary UX

Prefer categories such as:

Character.

Inventory.

Weapons.

Items.

Missions.

Progression.

Currency.

Skills.

Advanced Mode

Provide advanced/raw inspection for power users and developers.

Potential information:

Unknown fields.

Raw values.

IDs.

Nested structures.

Format metadata.

Serialization details.

Do not make raw editing the default.

Dangerous Operations

Make destructive or unusual operations obvious.

Examples:

Removing items.

Replacing large collections.

Editing unknown data.

Writing unsupported formats.

Overwriting saves.

Save Workflow

Current, accepted workflow:

Open original
↓
Timestamped backup (bl4editor_backups/)
↓
Edit
↓
Validate (invariants, rejected-item confirmation)
↓
Write temporary file, verify, atomic rename over the original

Saving is blocked while the game runs. Do not replace this with Save As.

Error Messages

Explain:

What failed.

Why it failed.

Whether the original file is safe.

What the user can do.

Avoid generic errors such as:

Invalid save.

UI Architecture

The UI should not know binary offsets, compression details, or low-level parser behavior.

Use application/domain operations instead.
